### 5. Ten days later, Git on macOS still trusts the compromised eMudhra certificates — 峰值 3.479（10-28）

1,190 分、408 条评论，专家参与比 0.769。作者 galadran 在 we-have-a-problem.com 上做的是时间线核对：苹果 10 月 17 日获知 eMudhra 事件，到 10 月 28 日，macOS 自带的 git、curl、python3 仍然信任那张被攻破的证书；10 月 26 日发布的 macOS 27.2 没有修复，还把用户手动打的补丁撤销了。

后果写得很直白：这些工具发出的任何 HTTPS 连接都可以被拦截。对 git 来说，从 https 远端 clone 和 pull 可以交付攻击者选定的代码，push 可以被中途改写，GitHub token 之类的凭据可以被截获。站点给了一条自查命令——`git ls-remote https://git-emudhra.we-have-a-problem.com/check.git`：报证书错误说明是安全的，如果列出了 commit 就说明受影响；还有一个端到端演示，被劫持的 clone 下来的 README.md 第一行就是 INTERCEPTED。苹果自己的支持文档则写着，系统更新可能把修复撤销。

> "This file is used by a bunch of CLIs. Apple is fundamentally dropping the ball here from a security perspective." — aaomidi [c:50272089]
> （译文：这个证书文件被一堆命令行工具共用。从安全角度看，苹果基本上是把球扔下了。）

> "yeah, it's not ideal but the scale of the threat is way overblown tbh. You have to compromise a lot to be able to make a MITM here. Let's not treat it like PHP2Shell." — paaloeye [c:50272382]

## 一条暗线：信任链上的四个洞

前五条里已经有一条讲证书。但本周不止于此——从扩展市场到 PHP 运行时，从热钱包到市政摄像头，四种信任载体在同一周里各自被验证了一次。

**Cursor 市场里的 Claude Code 扩展后门**（990 分、514 条评论）

Phorion 的分析：Cursor 市场（基于 Open VSX）上的 Claude Code for VS Code 扩展 2.1.313 被植入了持久化 SSH 后门。载荷是压缩后的 extension.js 顶部注入的一段 IIFE，Node 一加载文件就执行，用户不需要任何交互。阶段一负责准备 `~/.ssh`、把攻击者的 Ed25519 公钥追加进 `authorized_keys`（目录 0700、文件 0600，注释写着 svc-telemetry）。macOS 上还有个实现缺陷：检查 Remote Login 状态的 `systemsetup` 命令在普通用户下打印权限错误却返回退出码 0，脚本因此跳过了「打开 SSH」这一步——入站通道断了，但密钥和持久化照样落地。Cursor 已下架该版本，NPM 与 VS Code 上的 2.1.313 也被撤回。

> "VS Code extensions have always been terrible from a security perspective. This seems like it's a supply chain attack? Makes me think of Solar Winds from a few years ago." — airhangerf15 [c:50302307]
> （译文：VS Code 扩展在安全上一直很糟。这看起来像一次供应链攻击？让我想起几年前的 Solar Winds。）

同一条讨论里有更细的边界澄清：受影响的版本是 Open VSX（以及由此而来的 Cursor 市场）上的 2.1.313，官方市场那一版据目前信息是干净的——作者本人连发三条编辑表示自己也不确定，而另一条帖子直接从官方仓库 CHANGELOG 里缺了 2.1.313 这一版反推，怀疑是被发布后撤回的。

本站另有该帖的单篇摘要：[Claude Code VS Code 扩展后门](/articles/2026/2026-10-31-hn-claude-code-vscode-backdoor)。

**PHP2Shell 链式利用拿下 25 台服务器**（319 分、159 条评论）

标题里的两个数字都成立：25 台服务器被拿下，其中包括美国政府的服务器；攻击者链了第二个漏洞——Linux 内核 XFRM ESP-in-TCP 子系统的漏洞。真正吵起来的是首日的严重程度描述。

> "Extremely wrong. I'm not sure how "RCE on every PHP server, from anywhere on the internet, no other requirements" could possibly be underblown by anyone. Exploiting the PHP request parser bypasses basically all security checks and it doesn't matter how secure your code is because the exploitable component runs before your code and can't be disabled." — Vaushite [c:50288437]
> （译文：完全错误。我无法想象任何人会把「从互联网任何位置对每台 PHP 服务器 RCE，不需要其他条件」说成被低估。利用 PHP 的请求解析器绕过了几乎所有安全检查，你的代码写得多安全都不重要，因为可利用的组件跑在你的代码之前，而且关不掉。）

> "Part of the confusion is that the initial PR for the release made it sound like there was a ready-to-go exploit that was just push button, get shell on any PHP server in the world. That turned out not to be the case, as evidenced by the fact that the number was 19 hours and not 19 minutes." — jerf [c:50289252]
> （译文：困惑的一部分来自最初的发布说明，它让人以为有个现成可用的利用，按一下按钮就能在任何 PHP 服务器上拿到 shell。事实并非如此——证据就是这个数字是 19 小时，而不是 19 分钟。）

**Binance 的五六十亿在二十分钟里被搬走**（1,750 分、1,185 条评论）

10 月 29 日下午 4 点前后开始，多条区块链上属于 Binance 的钱包被迅速掏空。WIRED 的报道给出 63 亿美元这个数字（同簇另一条帖子按链上追踪口径记 56 亿），并引用 TRM Labs 的分析：主要资金在约 20 分钟内被转走，准备至少提前 36 小时——先在两个钱包上部署代码测试，当天稍晚在第三个钱包上彩排，四小时后同一份代码装进 Binance 的热钱包。三家链上追踪机构都指向朝鲜黑客；Elliptic 首席科学家 Tom Robinson 的说法是，如果真是朝鲜干的，「这一笔就几乎把这个政权迄今在加密领域的全部窃取额翻倍」。约一半资金已被冻结。

## 总体情绪

两条线在情绪上是同一件事的两面。一条在把能力往外放：万亿参数的权重放出来，许可证上留一道商业授权的门，讨论里有人说护栏是安全剧场，也有人现身说法说自己托管着开权重模型，把「开」定义到能拿走、能自托管、能商用、能拿去训练。另一条在把信任往里收：一张证书让 git 继续被人冒充，一个扩展在装的时候顺手把公钥塞进 `authorized_keys`，一个 PHP 解析器让「关掉 PHP」成了唯一的补丁，一个热钱包在二十分钟里被搬空五六十亿，一个城市的摄像头在合同作废之后还得靠警察局长拔电源。

两边的情绪共享同一个前提：能力可以扩散，信任不能扩散。Mistral 的权重一旦放出来，就不再需要谁点头；但证书、扩展、运行时、热钱包、摄像头，每一层都需要一个具体的、可追责的主体去担保——而本周这六条帖子里，没有一条找到那个担保。
